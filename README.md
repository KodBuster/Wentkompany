# WENTKOMPANY — новый сайт

Замена wentkompany.ru. Этап 3: каркас Next.js 15 + посадочная по нормам МЧС.

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить токены
npm run dev                  # http://localhost:3000
```

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm run build` / `npm start` | прод-сборка и запуск |
| `npm run data` | пересобрать `src/data/*.json` из выгрузки WooCommerce |
| `npm run check` | проверка расчётного ядра, компоновки, чертежа и DXF |
| `npm run check:ifc` | открывает сгенерированные IFC сторонним парсером web-ifc |

## 3D-ядро конфигуратора (этап 4)

Геометрия строится кодом из габаритов H/W/D, готовых моделей нет:

- корпус — усечённая пирамида (`CylinderGeometry` с 4 сегментами), завал стенок 16 % габарита, но не более 200 мм;
- крышка-фланец с патрубками: число и диаметр берутся из расчёта по скорости 8 м/с;
- жиросборный жёлоб и отбортовка по нижней кромке;
- лабиринтные кассеты: раскладка по открытым сторонам (3 у пристенных, 4 у островных);
- гидроконтур с форсунками и водяной завесой — только у ЗВПГ / ЗВОГ;
- приточная щель — только у ЗПВП / ЗПВО; подвесы — только у островных; светильники — опция.

Режимы просмотра: реализм, рентген, разнесённая схема с подписями узлов.
Отражения даёт процедурная карта окружения (canvas-градиент), без загрузки HDR со стороннего CDN.
Если WebGL недоступен, вместо сцены показывается предупреждение, а расчёт и спецификация продолжают работать.

Компоновка проверяется в `npm run check`: 6 семейств × 3 габарита — патрубки не вылезают за крышку,
кассеты не вырождаются, подвесы только у островных, форсунки только у гидро-изделий.

## 2D-чертёж (этап 5)

Чертёж строится из той же компоновки, что и 3D, — разойтись они не могут по построению.

- лист A3 420 × 297 мм, координаты SVG в миллиметрах листа (`viewBox` = размер листа),
  поэтому из тех же полилиний на этапе 6 собирается DXF без пересчёта;
- три проекции: вид спереди с патрубками, вид сбоку, план с осями, врезками и точками подвеса;
- у пристенных изделий в плане показывается стена, у островных — четыре точки подвеса;
- масштаб выбирается автоматически из ряда ГОСТ 2.302 (1:2 … 1:50) под габарит;
- размерные цепи с засечками и выносными линиями, штамп с обозначением `ВК.<артикул>.<H-W-D>`,
  массой, материалом, масштабом и статусом «Предварительно»;
- технические требования собираются из расчёта: расход, патрубки со скоростью, материал,
  число кассет, для гидро-изделий — отсылка к п. 5.30 СП 7.13130;
- кнопка «Скачать SVG» отдаёт лист файлом; PDF и DXF — этап 6.

Чертёж эталонного типоразмера встроен в карточку изделия, произвольный габарит — в конфигураторе.
`npm run check` проверяет 9 листов: масштаб из ряда, виды не вылезают за поля и не наезжают на штамп,
строки техтребований помещаются в рамку.

## Выгрузка (этап 6)

`POST /api/export` с телом `{ kind, slug, dims, material, options }`:

- `pdf` — лист чертежа A3, вектор, та же геометрия что на экране, кириллица встроенным шрифтом;
- `quote` — коммерческое предложение A4: состав, расчётные параметры, цена, срок, примечания и оговорка про оферту;
- `dxf` — чертёж для CAD в формате R12, **в натуральную величину 1:1**; масштаб назначается при печати из CAD;
- `ifc` — модель для BIM в IFC4 (см. ниже).

**Цену считает сервер.** Клиент присылает только выбор пользователя — модель, габариты, опции;
базовая цена берётся из каталога, расход и состав пересчитываются заново. Подменить сумму в КП
со стороны браузера нельзя. Габариты вне диапазонов отбрасываются на эталонный типоразмер,
неизвестный slug и неизвестный kind — ошибка.

Известные ограничения:

- DXF R12 не поддерживает Unicode, поэтому подписи транслитерируются (`Вид спереди` → `Vid speredi`).
  Геометрия и слои (CONTOUR / HIDDEN / AXIS / DIM / TEXT) полноценные. Переход на R2000 вернёт кириллицу.
- Размерные цепи в DXF — линии и текст, а не объекты DIMENSION: в R12 они требуют блоков.
- Шрифт для PDF лежит в `public/fonts` (DejaVu Sans Mono, свободная лицензия) — без него в PDF нет кириллицы.
- Полноценные BIM-параметрические семейства (Revit RFA) не делаем: IFC решает задачу переносимо.

### IFC для BIM (подэтап 6.1)

Зонт выгружается как **IfcAirTerminal** в схеме IFC4 с полной пространственной структурой
(проект → площадка → здание → этаж), иначе модель не встанет в чужой проект:

- тело корпуса — `IfcFacetedBrep` (усечённая пирамида по габаритам), патрубки — `IfcExtrudedAreaSolid`
  с круглым профилем; число и диаметр берутся из расчёта, а не задаются вручную;
- материал (`IfcMaterial`), базовые количества (`Qto_AirTerminalBaseQuantities`: масса, площадь, габариты);
- набор свойств `Pset_WENTKOMPANY_Configuration`: артикул, обозначение, габариты, расход воздуха,
  патрубки и скорость, периметр захвата, число кассет, признаки гидрозатвора и притока,
  а для гидро-изделий — ссылка на требования пп. 5.28–5.33 СП 7.13130.
  Ради этих свойств BIM-выгрузка и нужна: они едут в проект вместе с геометрией;
- `GlobalId` детерминирован от конфигурации — повторная выгрузка обновляет объект,
  а не плодит дубли в проекте.

Проверка не «на глаз»: `npm run check:ifc` открывает сгенерированные файлы **сторонним парсером
web-ifc**, находит зонт, читает свойства (расход в IFC сверяется с расчётом), количества и
триангулирует геометрию. Дополнительно проверяются сплошная нумерация сущностей STEP и
отсутствие висячих ссылок.

Кнопки выгрузки стоят и в конфигураторе, и в карточке изделия. Кнопка «Получить точную цену»
переносит конфигурацию в форму заявки (`/contacts?cfg=…`), и она же уходит в Telegram и вебхук CRM.

### Калькулятор окупаемости

`src/components/roi-calculator.tsx`. Считает **только экономию на чистках воздуховода**:
сокращение с 12 до 2 чисток в год при эффективной фильтрации (исследование по вентиляции горячих
цехов, КиберЛенинка). Пользователь задаёт стоимость одной чистки, число самостоятельных трактов
и бюджет на фильтрацию — всё остальное считается от этих трёх чисел.

Пожарный риск, простой кухни и штрафы **сознательно не переводятся в рубли**: такую оценку нечем
обосновать, а в КП она читается как приписка. Если производство даст свою статистику по чисткам,
менять нужно две константы в шапке файла.

### Кейсы

`src/data/cases.json` — пустой массив `items`, и пока он пуст, блок кейсов не рендерится вообще.
Выдуманных объектов на сайте производителя нет и не будет: они проверяются первым же звонком.
Формат записи (см. интерфейс `CaseRecord` в `src/components/cases.tsx`):

```json
{
  "slug": "kafe-na-vernadskogo",
  "title": "Мангальная линия в кафе",
  "city": "Москва",
  "kind": "Ресторан",
  "equipment": "Мангал 1200, тандыр",
  "supplied": "ЗВПГ 450/1600/900, ГФ, АВТ",
  "task": "Одно предложение о задаче.",
  "result": "Одно предложение о результате, без превосходных степеней.",
  "photo": "/cases/kafe-na-vernadskogo.jpg",
  "year": 2026
}
```

Пока кейсов нет, на лендингах стоит блок «Порядок работы» (`src/components/process.tsx`) —
последовательность шагов от замера до документов. Сроки в нём намеренно без цифр: их даёт
производство (см. открытые вопросы).

### Аналитика

Яндекс.Метрика подключается **только если задан `NEXT_PUBLIC_YM_ID`** — без переменной счётчик не
рендерится, `track()` молча ничего не делает, и на стенде в браузер не уходит ни одного запроса к
`mc.yandex.ru`. Цели (`src/lib/analytics.ts`):

| Цель | Когда срабатывает |
| --- | --- |
| `lead_sent` | заявка успешно принята сервером; параметр — приложена ли конфигурация |
| `export_file` | файл действительно скачан; параметры — вид файла и артикул |
| `configurator_open` | открыт конфигуратор |
| `compliance_gap` | в чек-листе отмечен пробел; параметр — пункт СП |
| `call_click` | клик по телефону в шапке, подвале или в CTA |

Цели создаются в интерфейсе Метрики как «JavaScript-событие» с этими идентификаторами.

### Шрифты

Все три гарнитуры лежат в `public/fonts` и объявлены в `src/app/fonts.css`:
из браузера посетителя **не уходит ни одного запроса к fonts.googleapis.com**.
Начертания первого экрана предзагружаются в `layout.tsx` — без этого крупный заголовок
перерисовывался и вся страница под ним прыгала (CLS 0,51 → 0,00).

Заголовочный шрифт пришлось поменять: **Saira Condensed не поддерживает кириллицу**,
то есть русские заголовки всё это время рисовались запасным Arial Narrow, а на macOS
и Linux — обычным гротеском. Вместо него Oswald: тот же узкий индустриальный характер,
но с полной кириллицей.

Файлы копирует `scripts/copy-fonts.mjs`, он же висит на `prebuild` — список начертаний
задан в нём одним массивом.

### Проверки

```
npm run check            # расчёты, компоновка, чертежи, DXF
npm run check:ifc        # IFC через сторонний парсер web-ifc
npm run check:redirects   # все 28 правил 301, sitemap, robots, 404, заголовки
npm run check:all        # всё вместе
```

`check:redirects` поднимает продакшен-сервер и требует, чтобы каждый старый адрес отдавал
301, вёл на живую страницу и не образовывал цепочку. Заодно проверяет, что каждый адрес
из `sitemap.xml` открывается.

### Мобильные

До этапа 8 на телефоне **не было навигации вообще**: меню скрыто до `lg`, и с узкого экрана
можно было попасть только на главную и в конфигуратор. Добавлен `MobileNav` — панель
с полным меню, телефоном и кнопкой конфигуратора, закрывается по переходу и по Esc.

Проверено на iPhone 13, iPhone SE и Pixel 7: горизонтального переполнения нет, 3D-сцена
рендерится, ошибок в консоли нет, цели нажатия на сенсорных экранах доведены до 44 px.

## Открытые вопросы к производству

1. **Формула цены нестандарта.** Сейчас — оценка `база × (S/S₀)^0.6`, помечается бейджем «предварительная оценка».
2. **Надбавки за опции и AISI 304.** Опции — «по запросу», 304 — оценочный коэффициент 1.18.
3. **ТТХ с чертежей:** толщина стали, шаг фильтров, Ø патрубков — в выгрузке их нет.
4. **Методика расхода воздуха.** Считается по геометрии захвата; сверить с расчётом по тепловыделению.
5. **Реквизиты, адрес производства, сроки, гарантия** — в `src/lib/site.ts` заглушки с TODO.
6. **Кейсы объектов** — нужны фото, состав поставки и согласие заказчиков (`src/data/cases.json`).
7. **Сроки производства и монтажа** — проставить в блоке «Порядок работы».
8. **Статистика по чисткам канала** — если есть своя, заменит константы 12 → 2 в калькуляторе.
