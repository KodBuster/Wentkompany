# Как вести сайт

Инструкция для человека без опыта разработки. Всё, что меняется регулярно —
цены, товары, контакты, кейсы — лежит в текстовых файлах. Код трогать не нужно.

После любой правки: `npm run build`, затем перезапуск (или `docker compose up -d --build`).
Перед выкладкой прогоняйте `npm run check:all` — он проверит расчёты, чертежи, IFC и редиректы.

---

## 1. Изменить цену

Цены живут в `src/data/catalog.json`, поле `price` у товара. Значение — число в рублях,
без пробелов и знака валюты.

```json
{
  "article": "ЗВПГ",
  "slug": "zonty-vytjazhnye-pristennye-s-gidrozatvorom-zvpg",
  "price": 45000
}
```

Цена базового типоразмера подставляется во все места сразу: карточку, каталог, лендинги,
конфигуратор, коммерческое предложение. Отдельно нигде править не нужно и **нельзя** —
иначе КП разойдётся с сайтом.

Цена нестандартного размера считается формулой от площади изделия и всегда помечается
как предварительная. Формулу задаёт `PRICE_EXPONENT` в `src/lib/calc.ts` — менять её должен
разработчик, вместе с производством.

## 2. Добавить или убрать товар

В том же `catalog.json`, массив `products`. Минимальный набор полей:

| Поле | Что это | Пример |
| --- | --- | --- |
| `article` | артикул | `ЗВП-4` |
| `slug` | адрес страницы латиницей | `zont-vytjazhnoj-pristennyj-tip-4` |
| `family` | код линейки: ЗВП, ЗВО, ЗПВП, ЗПВО, ЗВПГ, ЗВОГ, ПИР, ГФ, АВТ | `ЗВП` |
| `name` | название для человека | `Зонт вытяжной пристенный тип 4` |
| `price` | цена базового размера, ₽ | `10400` |
| `base` | габариты базового размера, мм | `{ "h": 350, "w": 1000, "d": 600 }` |
| `images` | пути к фото | `["/catalog/zvp-4.jpg"]` |

`slug` менять у существующего товара нельзя: по старому адресу уже ходят из поиска и из
писем. Если адрес всё же поменялся, добавьте правило в `src/data/redirects.json`
(`source` — старый адрес, `destination` — новый) и прогоните `npm run check:redirects`.

Товар исчезнет с сайта, если удалить его из массива. Страница начнёт отдавать 404 —
поэтому лучше не удалять, а добавить редирект на замену.

## 3. Поменять контакты и реквизиты

Один файл — `src/lib/site.ts`. Телефон, почта, адрес, часы работы, юрлицо.
Меняется в одном месте, подставляется в шапку, подвал, контакты, микроразметку и КП.

```ts
phone: '+7 495 000-00-00',
phoneHref: 'tel:+74950000000',   // без пробелов и скобок
email: 'info@wentkompany.ru',
```

`phoneHref` должен совпадать с `phone` по цифрам — по нему звонят с телефона.

## 4. Добавить кейс объекта

`src/data/cases.json`, массив `items`. Пока он пуст, блок кейсов на сайте
не показывается вовсе — это сделано намеренно, чтобы не выдумывать объекты.

```json
{
  "slug": "kafe-na-vernadskogo",
  "title": "Мангальная линия в кафе",
  "city": "Москва",
  "kind": "Ресторан",
  "equipment": "Мангал 1200, тандыр",
  "supplied": "ЗВПГ 450/1600/900, ГФ, АВТ",
  "task": "Одно предложение о задаче.",
  "result": "Одно предложение о результате.",
  "photo": "/cases/kafe-na-vernadskogo.jpg",
  "year": 2026
}
```

Фото кладите в `public/cases/`. Перед публикацией нужно согласие заказчика на упоминание
объекта — это не формальность, а защита от претензий.

## 5. Фотографии товаров

Лежат в `public/catalog`. Какие показывать — задаёт таблица `LOCAL_IMAGES`
в `scripts/build-data.mjs`, первая в списке становится главной:

```js
'ЗВПГ': ['/catalog/zvpg-1.webp', '/catalog/zvpg-4.webp'],
```

Положите новые файлы в `public/catalog`, пропишите их в таблице и выполните
`npm run data`, затем `npm run build`.

Текущие фото временные: они вырезаны из скриншотов старого сайта, поэтому на
них остался водяной знак и невысокое разрешение. Как появятся оригиналы с
производства — заменить в первую очередь.

Нейтральное оборудование живёт отдельно: файлы в `public/nejtralnoe`, список —
в `src/data/neutral.json`.

## 6. Тексты страниц

Каждая страница — отдельный файл в `src/app/`:

| Страница | Файл |
| --- | --- |
| Главная | `src/app/page.tsx` |
| Нормы МЧС | `src/app/normy-mchs/page.tsx` |
| Для общепита | `src/app/dlya-obshchepita/page.tsx` |
| Для частного дома | `src/app/chastnyy-dom/page.tsx` |
| Контакты | `src/app/contacts/page.tsx` |
| Политика | `src/app/privacy/page.tsx` |
| Нейтральное оборудование | `src/app/eshchyo-delaem/page.tsx` |

Тексты в этих файлах лежат наверху, в списках `PAINS`, `FAQ`, `SITUATIONS` и подобных —
это обычные строки в кавычках. Правьте текст внутри кавычек, кавычки и запятые не трогайте.

## 7. Подключить Метрику

Задайте `NEXT_PUBLIC_YM_ID` в `.env` (номер счётчика цифрами) и пересоберите.
Пока переменная пуста, счётчик не подключается и в браузер посетителя не уходит
ни одного запроса к Яндексу.

Цели создаются в интерфейсе Метрики как «JavaScript-событие» с идентификаторами:
`lead_sent`, `export_file`, `configurator_open`, `compliance_gap`, `call_click`.

## 8. Заявки

Куда падают заявки, задают переменные в `.env`:

- `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — сообщение в Telegram;
- `CRM_WEBHOOK_URL` — вебхук amoCRM, Битрикс24 или своего приёмника.

Если ничего не задано, заявка не теряется: она пишется в журнал сервера. Но полагаться
на это нельзя — настройте хотя бы Telegram до запуска.

### Чертежи от заказчиков

К заявке можно приложить чертёж или эскиз: фото, PDF или DXF до 10 МБ. Файл уходит
в Telegram вместе с заявкой и **на сервере не сохраняется** — искать его в папках
не нужно, он лежит в переписке бота.

В CRM уходит только имя файла: сам файл живёт в Telegram у менеджера.

Формат проверяется по первым байтам файла, а не по названию, поэтому переименованный
`.exe` под видом картинки не пройдёт. Если заказчику нужно прислать что-то другое —
архив, чертёж в формате DWG, файл больше 10 МБ, — форма попросит воспользоваться
почтой или мессенджером.

## Чего делать не нужно

- **Править цену в двух местах.** Она берётся только из `catalog.json`. Сервер пересчитывает
  цену для КП сам, поэтому «поправить в вёрстке» не сработает и создаст расхождение.
- **Менять `slug` у живого товара.** Ломает ссылки и поисковую выдачу.
- **Ставить фото по ссылке на сторонний сайт.** Картинки должны лежать в `public/`,
  иначе они пропадут, когда тот сайт изменится.
- **Обещать сроки и гарантии в текстах, не согласовав с производством.** Всё, что
  на сайте написано цифрами, спросят при первом же разговоре.
- **Выкладывать без `npm run check:all`.** Проверка занимает минуту и ловит расхождения
  расчёта, битые редиректы и сломанные выгрузки.

## Если что-то сломалось

1. `npm run build` — покажет ошибку и файл, где она.
2. Чаще всего это лишняя или потерянная запятая в JSON. Проверить файл можно на любом
   валидаторе JSON или командой `node -e "require('./src/data/catalog.json')"`.
3. Откатите последнее изменение и соберите заново — сайт продолжит работать на предыдущей
   версии, пока новая не собралась.
