# Запуск на Timeweb Cloud

Все шаги по порядку. Отдельно отмечено то, что нужно сделать до переключения домена.

---

## 1. Сервер

Timeweb Cloud, Ubuntu 24.04, минимум 2 vCPU / 2 ГБ. Хостинг в РФ — данные заявок
не покидают страну (152-ФЗ).

```bash
apt update && apt install -y docker.io docker-compose-plugin nginx certbot python3-certbot-nginx
```

## 2. Картинки

Все изображения уже локальные — лежат в `public/catalog` и `public/nejtralnoe`,
зависимости от старого домена нет, `images.remotePatterns` из `next.config.ts` убран.
Специальных действий перед переключением домена не требуется.

Текущие снимки временные: вырезаны из скриншотов старого сайта, поэтому на них
водяной знак и экранное разрешение. Как появятся оригиналы с производства —
положить их в `public/catalog` и поправить `LOCAL_IMAGES` в `scripts/build-data.mjs`
(см. `docs/vedenie-sajta.md`).

Скрипт `npm run images` остался на случай, если понадобится добрать что-то со старого
сайта: он скачивает файлы, транслитерирует кириллические имена и переписывает пути.
Запускать его нужно там, где старый сайт ещё открывается, и до переключения домена.

## 3. Переменные

```bash
cp .env.example .env
```

Заполнить:

| Переменная | Значение |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://wentkompany.ru` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | куда падают заявки |
| `CRM_WEBHOOK_URL` | приёмник CRM, если есть |
| `NEXT_PUBLIC_YM_ID` | номер счётчика Метрики |
| `ENABLE_HSTS` | `0` сейчас, `1` после пункта 6 |

`NEXT_PUBLIC_*` вшиваются в бандл при сборке — после их изменения нужна пересборка,
а не только перезапуск.

## 4. Сборка и запуск

```bash
npm ci
npm run check:all            # расчёты, чертежи, DXF, IFC, редиректы
docker compose up -d --build
curl -I http://127.0.0.1:3000/   # ожидаем 200
```

Контейнер слушает только localhost — наружу его выставляет nginx.

## 5. nginx

```nginx
server {
    listen 80;
    server_name wentkompany.ru www.wentkompany.ru;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Форма принимает чертёж до 10 МБ — с запасом на служебные поля multipart.
    # Меньшее значение обрежет загрузку, и посетитель получит 413 без объяснения.
    client_max_body_size 12m;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

`X-Forwarded-For` обязателен: по нему работает ограничение частоты заявок
(5 за 10 минут с адреса). Без него все заявки будут выглядеть как с одного IP.

## 6. Домен и сертификат

1. A-запись `wentkompany.ru` и `www` → IP сервера.
2. Дождаться распространения DNS (`dig wentkompany.ru +short`).
3. `certbot --nginx -d wentkompany.ru -d www.wentkompany.ru`
4. Проверить, что `https://wentkompany.ru` открывается и редирект с http работает.
5. Только теперь `ENABLE_HSTS=1` в `.env` и пересборка. Заголовок заставляет браузеры
   ходить только по https целый год — включать его до рабочего сертификата опасно.

## 7. Проверка после переключения

```bash
npm run check:redirects      # прогонит все 28 старых адресов
```

Вручную:

- главная, каталог, карточка товара, конфигуратор — открываются;
- в конфигураторе крутится 3D и скачиваются PDF, КП, DXF, IFC;
- заявка с формы дошла в Telegram;
- заявка **с приложенным чертежом** (фото или PDF) дошла в Telegram вместе с файлом —
  если файл не доходит, а заявка доходит, проверьте `client_max_body_size` в nginx;
- `https://wentkompany.ru/sitemap.xml` и `/robots.txt` отдаются;
- старый адрес вида `https://wentkompany.ru/product/...` уводит на новую карточку.

Затем:

- Яндекс.Вебмастер: подтвердить сайт, отправить `sitemap.xml`, проверить переезд;
- Метрика: убедиться, что визиты идут, создать пять целей (см. `docs/vedenie-sajta.md`).

## 8. Резервные копии

Сайт не хранит состояние: вся информация лежит в репозитории. Достаточно бэкапа
репозитория и файла `.env`. Отдельная резервная копия нужна только для `public/catalog`
и `public/cases`, если фотографии добавляли прямо на сервере.

## Откат

Образ собирается из репозитория, поэтому откат — это возврат к предыдущему коммиту:

```bash
git checkout <предыдущий-коммит>
docker compose up -d --build
```

Пока новый образ собирается, работает старый контейнер: простоя нет.

## Что проверить перед самым запуском

- [ ] `src/lib/site.ts` — телефон, почта, адрес, юрлицо заполнены (сейчас там заглушки)
- [ ] Telegram или CRM принимают заявки
- [ ] `npm run check:all` проходит целиком
- [ ] проверена отправка заявки с файлом 5–9 МБ (лимит nginx и Telegram)
- [ ] политика конфиденциальности отражает реальный состав данных
- [ ] сроки производства и гарантия в текстах согласованы с производством
