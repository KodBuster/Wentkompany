# Structured data audit — fortinox.ru

Дата проверки: 2026-11-01. Решения от 2026-11-01 внесены в код, деплой не выполнялся.

Принято: эталон под заказ (`MadeToOrder`, не `InStock`); витринная цена гидрофильтра 129 600 ₽ уже считается из исходных 120 000 ₽ в `data/prices.json` (сначала −10 %, затем +20 %) — исходник прайса не менялся; в Offer записано «цена эталонного типоразмера». Крошки карточки и линейки включают «Каталог». FAQ идёт через `JsonLd`.

Стек: Next.js 15.5 (`next@^15.5.24`), React 19, App Router, статические страницы каталога и блога. JSON-LD собирается в серверных компонентах и попадает в HTML без клиентского рендера. Общий вывод — `src/components/json-ld.tsx` (экранирует `<`). Идентификаторы — `src/lib/seo.ts`: `https://fortinox.ru/#organization`, `https://fortinox.ru/#website`.

Разметка не гарантирует позиции в Google и цитирование в AI-поиске. Ниже — только соответствие видимому контенту и правилам Schema.org / ограничениям rich results.

## Проблемы

### P0 — не менять без подтверждения

1. **Наличие `InStock` при изготовлении под размер.**  
   `src/app/catalog/[slug]/page.tsx:244`. На странице бейдж «цена для эталонного типоразмера» (`page.tsx:288`) и сценарий заказа/конфигуратора. В проде у гидрофильтра и ЗВПГ в Offer стоит `https://schema.org/InStock`. Для Google Merchant допустимы в том числе InStock, OutOfStock, PreOrder, BackOrder. `MadeToOrder` есть в Schema.org, но не входит в список availability для товарных rich results. Пока складской статус эталона не подтверждён, поле лучше убрать или заменить только после вашего ответа. Сейчас это расхождение с видимым смыслом «эталон / по размерам».

2. **Цена гидрофильтра: git 120000, прод 129600.**  
   В `src/data/catalog.json:133` цена ГФ — `120000`. В HTML `https://fortinox.ru/catalog/gidrofiltr` и видимая цена, и Offer равны `129600`. Генератор подставляет `p.price` и сам цену не умножает. Расхождение данных деплоя и репозитория, не ошибка сериализации. Какую цифру считать прайсом — нужно подтвердить. В разметку другую сумму не подставлять.

### P1 — низкий риск, ждут одобрения перед правкой кода

3. **Крошки короче видимой навигации.**  
   Видимый путь карточки: Главная / Каталог (`/#catalog`) / линейка / изделие (`page.tsx:261–269`). JSON-LD (`page.tsx:251–255`) пропускает «Каталог». У гидрофильтра в проде два пункта: Главная → Гидрофильтр. Линейка из одного изделия в крошки не входит — это согласовано с каноникалом. Добавление пункта «Каталог» → `https://fortinox.ru/#catalog` повторяет меню и не создаёт новый URL.

4. **Offer не поясняет, что цена эталонная.**  
   Сумма совпадает с цифрой на странице, но у Offer нет оговорки бейджа. Для машины это выглядит как цена любого исполнения. Безопасное уточнение — текст Offer вроде видимого бейджа, без новой суммы и без `priceSpecification` с выдуманной единицей.

5. **FAQ обходит экранирование.**  
   `normy-mchs/page.tsx:352`, `dlya-obshchepita/page.tsx:310`, `chastnyy-dom/page.tsx:240`, `nestandartnyy-zont/page.tsx:274`. Замена на `<JsonLd>` не меняет текст вопросов.

### P2 — по желанию, не в этом проходе

6. **Имя Product и H1.** H1 срезает хвостовые скобки (`page.tsx:277`), в schema остаётся полное `p.name`, например «… (ЗВОГ)».
7. **BlogPosting без картинки.** Общий `og-image.jpg` — фото зонта, не иллюстрация статьи. Не подставлять его как `image` статьи. Даты в проде есть (`datePublished` / `dateModified` у `/blog/gidrofiltr` из git). Если сборка на Amvera когда-нибудь пройдёт без истории git, даты пропадут — так и задумано в `src/lib/blog.ts:125–128`.
8. **АВТ без Product.** Цены нет, Offer нет. Product без offers можно добавить позже; rich result товара Google без цены не покажет.
9. **Линейки без ItemList.** Не ошибка. Список типоразмеров уже есть в HTML.
10. **`additionalProperty` из расчётной таблицы.** Цифры уже на странице (`calculate`). В schema их не копировал: это инженерные величины, их лучше сверять отдельно.

Не добавлять: LocalBusiness (нет улицы и юрлица), рейтинг и отзывы, Service, логотип, sameAs мессенджеров, WebPage на каждую страницу, SKU и цену конфигуратора.

## Что уже в порядке

- Один Organization и один WebSite на страницу, стабильные абсолютные `@id`.
- Product только у реального изделия с ценой; гидрофильтр не размечен как гидрозонт.
- Автор статьи — организация, персонального автора нет.
- FAQPage построен из того же массива, что и видимые вопросы.
- Рейтингов и наград нет.
- `<` в общем хелпере экранируется (`json-ld.tsx:6`).
- Разметка в исходном HTML, не после гидрации.

## Проверки, которые не запускались

- Google Rich Results Test и Schema Markup Validator: нет программного доступа из этой сессии. JSON с прода разобран вручную и синтаксически валиден.
- `lint` / `typecheck` / `build` не запускались: код приложения не менялся.
- FAQ rich results у Google с 2023 года ограничены узким кругом сайтов. Валидный FAQPage на `/normy-mchs` не означает расширенный сниппет.
- Breadcrumb и Product могут давать сниппеты; Offer с неверным availability этому мешает, а не помогает.

## Что подтвердить вручную

1. Эталонные типоразмеры считаются в наличии (`InStock`) или делаются под заказ?
2. Прайс гидрофильтра для сайта — 120 000 ₽ из репозитория или 129 600 ₽ с прода?
3. Нужен ли в Offer явный текст «цена эталонного типоразмера»?

После ответов можно внести только пункты 3–5 (крошки, оговорка цены, `JsonLd` для FAQ) и отдельно решение по availability. Пункты 1–2 в код без ответа не переносить.
